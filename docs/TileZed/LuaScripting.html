Lua scripting in TileZed

TileZed embeds Lua 5.2.1 for map editing and mapping automation. This is an editor API: it does not execute Project Zomboid gameplay scripts and it is not the API exposed by the game.

BuildingEd has a separate transactional API and global building object. See the BuildingEd Lua scripting reference.

The authoritative binding is src/tiled/luatiled.pkg. The ready-to-run examples installed in the lua directory use only functions exposed by that binding.

Execution modes

ModeHow to run itGlobalsSaving
Current map Tools > Lua Console > Run Script map, app, scriptDirectory Changes are added to the current TileZed undo stack.
TMX directory Lua Console > Run In Directory map, app, scriptDirectory Selected TMX files are rewritten only when changed. Enable backups.
WorldEd world Lua Console > Run On World map, app, scriptDirectory Existing TMX cells in the selected PZW are processed. Enable backups.
Interactive tool Declare a tool in LuaTools.txt, then select it in TileZed. map, self, scriptDirectory The tool calls self:applyChanges("Undo label").

scriptDirectory is the absolute directory containing the running script. Use it to include a companion file:

dofile(scriptDirectory .. "/shared-functions.lua")

When a TMX belongs to a loaded WorldEd project, map:cellX() and map:cellY() return its absolute world-cell coordinates. They return -1 when that context is not available.

Your first script

Save this as UTF-8, open a map, and run it from the Lua Console:

print(("Map: %d x %d tiles, levels %d to %d")
    :format(map:width(), map:height(), map:minLevel(), map:maxLevel()))

print(("World cell: %d,%d"):format(map:cellX(), map:cellY()))

for index = 0, map:layerCount() - 1 do
    local layer = map:layerAt(index)
    print(("[%d] %s (%s)")
        :format(index, layer:nameWithPrefix(), layer:type()))
end

The installed file lua/example-inspect-map.lua contains a longer read-only version.

Important rules

  • Tile coordinates and API collection indexes are zero-based. Lua tables returned as lists are still iterated normally with ipairs(), starting at one.
  • layerAt(0), tilesetAt(0), and objectAt(0) access the first element.
  • Always test lookup results. A missing layer, tileset, tile or rule returns nil.
  • Layer lookups use the level-prefixed name, for example 0_Floor, 8_RoomDefs, or -1_Floor. layer:name() returns the unprefixed name; layer:nameWithPrefix() returns the lookup name.
  • The complete available tileset catalog is loaded before scripts can run. Tile lookup, placement, deletion and replacement are synchronous and require no callbacks.
  • Batch changes are collected and then applied through TileZed. Do not call map:write() to overwrite the current map; that function is intended for writing a separate map or a map created in Lua.
  • Run scripts that modify many TMX files on a copy first and keep the batch backup option enabled.
  • Use UTF-8 for scripts, paths, object names and custom properties.

Batch examples

Inspect tilesets and used tiles

for index = 0, map:tilesetCount() - 1 do
    local tileset = map:tilesetAt(index)
    print(("tileset[%d] = %s"):format(index, tileset:name()))
end

local floor = map:tileLayer("0_Floor")
if floor then
    local tile = floor:tileAt(10, 20)
    if tile then
        print(("10,20 = %s_%d")
            :format(tile:tileset():name(), tile:id()))
    end
end

Fill the current selection

local layer = assert(map:tileLayer("0_Floor"), "Missing layer 0_Floor")
local tile = assert(
    map:tile("floors_interior_tilesandwood_01_0"),
    "Edit TILE_NAME in the script: this tile is not loaded")
local selection = map:tileSelection()

if selection:isEmpty() then
    error("Select one or more tiles before running this script")
end

layer:fill(selection, tile)
print(("Filled %d selection rectangle(s)"):format(selection:rectCount()))

A configurable version is installed as lua/example-fill-selection.lua.

Create a RoomDefs layer and object

local layerName = "8_RoomDefs"
local roomDefs = map:objectLayer(layerName)

if not roomDefs then
    roomDefs = map:newObjectLayer(layerName)
    map:addLayer(roomDefs)
    print("Created " .. layerName)
end

local room = MapObject:new("example_room", "RoomDef", 20, 20, 12, 8)
room:setProperty("usage", "documentation example")
roomDefs:addObject(room)

print(("RoomDefs now contains %d object(s)"):format(roomDefs:objectCount()))

See lua/example-roomdefs.lua for a version that first checks whether the example object already exists.

List and update object properties

local zones = map:objectLayer("0_Zones")
if zones then
    for _, object in ipairs(zones:objects()) do
        print(object:name(), object:type(), object:shape())
        for _, propertyName in ipairs(object:propertyNames()) do
            print("  " .. propertyName .. " = " .. object:property(propertyName))
        end

        if object:type() == "TownZone" then
            object:setProperty("reviewed", "true")
        end
    end
end

Paint an exact BMP color

local mainBmp = map:bmp(0) -- 0 = Map.png, 1 = Map_veg.png
local oldColor = rgb(128, 64, 32)
local newColor = rgb(130, 66, 34)

for y = 0, map:height() - 1 do
    for x = 0, map:width() - 1 do
        if mainBmp:pixel(x, y) == oldColor.pixel then
            mainBmp:setPixel(x, y, newColor)
        end
    end
end

Interactive tools

An interactive tool is loaded from an entry in the application or user LuaTools.txt:

tool
{
    label = Example Painter
    icon = tool-example.png
    script = tool-example.lua
    dialog-title = Example Painter
}

The script may define these callbacks:

activate() — tool selected.
deactivate() — tool deselected.
mouseMoved(buttons, x, y, modifiers)
mousePressed(buttons, x, y, modifiers)
mouseReleased(buttons, x, y, modifiers)
modifiersChanged(modifiers)
options() and setOption(name, value) — optional tool-dialog integration.

buttons.left, buttons.right, modifiers.alt, modifiers.control, and modifiers.shift are true when active. Mouse coordinates are floating-point tile coordinates at the current level.

local tileName = "floors_interior_tilesandwood_01_0"

function activate()
    self:setCursorType(TileTool.EdgeTool)
end

function mouseMoved(buttons, x, y, modifiers)
    self:clearToolTiles()
    local tile = map:tile(tileName)
    local layer = self:currentLayer()
    if tile and layer then
        local point = Region:new()
        point:unite(math.floor(x), math.floor(y), 1, 1)
        self:setToolTile(layer:nameWithPrefix(), point, tile)
    end
end

function mouseReleased(buttons, x, y, modifiers)
    if buttons.left then
        local layer = self:currentLayer()
        local tile = map:tile(tileName)
        if layer and tile then
            layer:setTile(math.floor(x), math.floor(y), tile)
            self:applyChanges("Example Painter")
        end
    end
end

The shipped tools tool-edge.lua, tool-curb.lua, tool-fence.lua, and tool-parking-stall.lua are complete examples with preview, dragging, cancellation and undo.

API reference: application actions

The global app requests existing TileZed Qt actions. Requests run only after the script succeeds and its map transaction has entered the Undo stack.

app:availableActions() returns save, saveAs, export, exportBinary, convertToLot, mapProperties, launchBuildingEd, and launchWorldEd.
app:invoke(actionName) queues one whitelisted action. Dialog-based actions open their normal Qt dialog.
local floor = assert(map:tileLayerAt(0, "Floor"))
assert(floor:setTileByName(10, 20, "floors_interior_tilesandwood_01_0"))
app:invoke("exportBinary")
Lua does not expose arbitrary QObject construction, widget ownership, signals, or slots. Use the explicit action list. In-game map feature generation is a WorldEd operation, not a TileZed action. Avoid dialog actions in directory/world batch scripts because the request is executed once for every processed map.

Detailed function behavior

This section complements the signature list with return values, side effects and practical limitations. “Recorded change” means that a current-map batch script will place the change on TileZed's Undo stack after the script completes. Interactive tools must additionally call self:applyChanges().

Map construction, identity and dimensions

FunctionReturns / effectUsage notes
Map:new(orientation, width, height, tileWidth, tileHeight) A new in-memory map. Use this only when generating a separate TMX. The global map already wraps the current document.
orientation() A Map.* enum. PZ maps normally use level-isometric geometry. Do not change coordinate assumptions based only on the visual camera.
width(), height() Map dimensions in tiles. Valid tile/BMP coordinates range from zero through width - 1 and height - 1.
minLevel(), maxLevel() The lowest and highest level found among layers. Both return zero for a map containing no layer outside level 0. Negative values identify basements.
cellX(), cellY() Absolute WorldEd cell coordinates, or -1. Coordinates are available when TileZed can associate the TMX with a loaded WorldEd project. A standalone TMX has no world-cell identity.

Layer lookup and structure

FunctionReturns / effectUsage notes
layerCount() Number of map layers. Use 0 .. layerCount()-1 with layerAt().
layerAt(index) A Layer, or nil outside the valid range. The index is zero-based and follows the map's layer order.
layer(name) Any layer matching the exact level-prefixed name. Use names such as 0_Floor, 8_RoomDefs and -1_Walls.
tileLayer(name), objectLayer(name) The requested typed layer, or nil. These combine an exact lookup with a type check and are preferable to calling asTileLayer() manually.
newTileLayer(name), newObjectLayer(name) A detached new layer sized to the current map. A numeric prefix is parsed as its level. The returned layer is not part of the map until passed to addLayer() or insertLayer().
addLayer(layer) Appends a detached or previously removed layer. Adding the same layer object twice is ignored.
insertLayer(index, layer) Inserts a layer and records a structural change. The index is clamped to the valid insertion range, so a negative index becomes the first position and a large index becomes the end.
removeLayer(index) Removes the indexed layer and records a structural change. An invalid index is ignored. Resolve the index immediately before removal because earlier removals shift later indexes.
layer:name() The base name without its level prefix. A level-8 RoomDefs layer normally returns RoomDefs.
layer:nameWithPrefix() The canonical lookup name. Prefer this value when comparing layers or passing a layer name to another API function.
layer:type() The layer type name. Use the typed conversion functions for logic; the type string is most useful for reports and diagnostics.
asTileLayer(), asObjectGroup() A typed wrapper or nil. These never convert a layer; they only test its existing type.

Tilesets and tile identity

FunctionReturns / effectUsage notes
tilesetCount(), tilesetAt(index) The map's referenced tileset count and a zero-based lookup. This reports tilesets attached to the TMX wrapper, not every entry in the global Tilesets.txt catalog.
tileset(name) The exact named Tileset or nil. Names are case-sensitive in the current binding. This is important for future Linux compatibility.
addTileset(tileset) Adds a tileset reference to the in-memory map. Passing a tileset already attached to the map is ignored.
tile("tileset_name_id") A Tile or nil. The final underscore separates the numeric ID, so tileset names may themselves contain underscores. Leading zeroes in the ID are accepted. The tileset must be present in the preloaded catalog.
tile(tilesetName, id) A Tile or nil. Useful when the name and ID are already separate. The tileset must be known to the map/catalog and available in the preloaded catalog. A 1x image is not required when a usable 2x or custom variant exists.
tile:id() Numeric ID within the tile's tileset. This is not a globally unique ID; combine it with tile:tileset():name().
tile:tileset(), tileset:name() The owning Tileset and its name. These are read-only identity helpers.
noneTile() The editor's special empty-tile sentinel. Passing it to setTile() or a fill operation clears the cell. clearTile() is clearer for a single coordinate.
replaceTilesByName(pairs) Replaces semicolon-separated from/to pairs across all tile layers. Example: "old_set_3;new_set_9;old_set_4;new_set_10". The complete string must contain an even number of valid names. The legacy function does not return an error object, so verify results.

TileLayer editing

FunctionReturns / effectUsage notes
level() The layer's integer level. Basement layers return negative values.
tileAt(x, y) The Tile at a coordinate, or nil. nil may mean either an empty cell or an out-of-bounds coordinate; validate coordinates when that distinction matters.
setTile(x, y, tile) Records one changed tile. Out-of-bounds writes are ignored. The special noneTile() sentinel is converted to an empty cell.
clearTile(x, y) Records one tile deletion. Equivalent to setting an empty tile, but more explicit.
erase(...) Clears a rectangle, Region or complete layer. Input areas are clipped to the layer. The no-argument form can create a very large Undo change.
fill(..., tile) Fills a rectangle, Region or complete layer. Region fills operate on every rectangle in the Region. Prefer a selected Region when only part of a layer should change.
replaceTile(oldTile, newTile) Returns true if at least one cell was replaced. Only this TileLayer is scanned. Use noneTile() as the new value to erase matches.

Selection and integer geometry

FunctionReturns / effectUsage notes
tileSelection() A copy of the current TileZed selection as a Region. It may contain multiple disjoint rectangles.
setTileSelection(region) Records a new editor selection. This changes selection state, not tile content.
Region:new() An empty integer region. Add rectangles with unite().
boundingRect() The smallest Rect covering the Region. The bounding rectangle may include holes or space between disjoint rectangles; use rects() for exact coverage.
rects(), rectCount() A one-based Lua list of component Rects and its count. Iterate the returned list with ipairs().
isEmpty() True when the Region contains no coordinate. Check this before a selection-based destructive edit.
unite(...) Mutates the Region by adding an area. Overlapping rectangles are normalized by Qt's region engine.
intersect(...) Mutates the Region, retaining only common area. Use this to clip a selection to safe map bounds.
intersected(...) A new Region; the original is unchanged. Choose this form when the source Region is needed later.
translated(dx, dy) A shifted copy of the Region. Coordinates remain integers.
Rect:new(x, y, w, h) An integer rectangle. A non-positive width or height represents no useful tile area.
x/y/width/height Rectangle origin and size. The origin is the top-left tile coordinate.
left/right/top/bottom Inclusive Qt rectangle edges. For a width of 10, right() is left() + 9.
translate(dx, dy) Mutates the Rect. translated() returns a shifted copy instead.
intersects(other) True when two Rects share at least one cell. Touching just outside an inclusive edge is not an intersection.

Map BMP data, aliases, rules and blends

FunctionReturns / effectUsage notes
bmp(0), bmp(1) Main and vegetation MapBmp wrappers. Use only indexes 0 and 1. The images use map-tile coordinates.
pixel(x, y) A packed RGB integer. Compare with rgb(r,g,b).pixel. An out-of-bounds read returns packed black, so bounds should be checked by the script.

reloadRules(), reloadBlends() Rereads the configured rule or blend file. Previously held Lua rule/alias/blend wrappers may become invalid; reacquire them after reload.
noBlend(layerName) A MapNoBlend mask for a layer. The mask is created lazily if needed.
MapNoBlend:get(x,y) The current boolean mask value. Used to suppress automatic blending at exact coordinates.
MapNoBlend:set(x,y,value), set(region,value) Records mask changes. The Region overload is convenient for selections and tool previews.

Color and file output

FunctionReturns / effectUsage notes
Color:new() Black. Equivalent to rgb(0,0,0).
Color:new(r,g,b), rgb(r,g,b) A Color with r, g, b and packed pixel fields. rgb() is the shorter form used by shipped scripts.

Interactive TileTool behavior

FunctionReturns / effectUsage notes

Interactive callbacks and options

Callbacks are optional. TileZed invokes only those present in the script.

deactivate()The tool is switched away.TileZed clears previews, closes the Lua state and releases wrappers afterward.

Every option descriptor needs unique name, visible label and type fields:

function options()
    return {
        { name="erase", label="Erase", type="bool", default=false },
        { name="width", label="Width", type="int",
          min=1, max=20, default=3 },
        { name="style", label="Style", type="enum",
          choices={"Concrete", "Asphalt"} },
        { name="variant", label="Variant", type="list",
          items={"A", "B", "C"} },
        { name="prefix", label="Tile prefix", type="string",
          default="street_01" }
    }
end

function setOption(name, value)
    self[name] = value
end

An enum callback receives the selected string. A list callback receives a one-based numeric index. Integer values are clamped to min..max. Invalid saved enum values fall back to the first choice, and all option values are stored under the script's base filename.

Perlin noise

Perlin:new() A deterministic Perlin generator. Create one generator and reuse it across the coordinate loop.
perlin(x,y,z) A smooth deterministic noise value. Scale coordinates to control feature size. Keep z constant for a 2D field or vary it to create another deterministic layer.

Errors, undo and cancellation

  • Use assert(value, "message") for required layers and tiles. Errors include a Lua traceback in the console.
  • print() writes to the Lua Console. UTF-8 is attempted first, with a Latin-1 fallback for old scripts.
  • Batch scripts show progress and can be cancelled. Cancellation is cooperative and checked periodically while Lua code is running.
  • A failed batch script is not applied to the current map. Directory and world modes stop on the first failed map.
  • Interactive tools must call self:applyChanges() after a successful edit. Preview calls alone do not change the map.

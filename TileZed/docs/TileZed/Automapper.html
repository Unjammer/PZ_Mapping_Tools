TileZed Automapper

Automapper matches tile or object patterns in a working TMX and copies the corresponding output from one or more rule-map TMX files. The Automapper dock shows loaded files, target layers, pattern counts, map properties, warnings, and errors.

Loading rules

Save the target map first. TileZed searches beside it for rules.txt. Each non-empty line that does not begin with # or // names either a rule-map .tmx or another .txt list:

# paths are relative to this list
rules/roads.tmx
rules/vegetation.txt
C:/shared-rules/signs.tmx

Relative paths are resolved against the list containing them. Nested lists are supported. Recursive includes, duplicate rule maps, missing files, and unsupported extensions are reported rather than loaded repeatedly.

Rule-map layer names

NamePurpose
RegionsDefines both input and output extents. Each connected region is one pattern.
RegionsInputInput matching extent when it differs from output.
RegionsOutputOutput copy extent when it differs from input.
Input_TargetPositive pattern matched against tile layer or Object Group Target.
InputNot_TargetPattern that must not match Target.
Output_TargetTiles or objects copied to target layer/group Target.

Prefixes are case-insensitive. The underscore is required. The part after it is the exact target layer name and type.

Indexes and alternatives

An optional index between the prefix and underscore groups conditions and outputs:

Input1_Ground
InputNot1_Objects
Output1_Floor
Output1_Furniture

Input2_Ground
Output2_Floor

For input groups, every named target inside one index must match; matching any complete index is sufficient. Repeated Input or InputNot layers with the same index and target provide accepted or rejected alternatives.

Each distinct Output index is an alternative output group. When several exist, Automapper chooses one randomly for each match. Give layers the same output index when they must be copied together.

Rule-map properties

PropertyMeaning
DeleteTilesClears affected output areas before copying output, removing results left by an older match.
AutomappingRadiusExpands the edited region by this many tiles during interactive automapping.
NoOverlappingRulesPrevents output regions produced by the same rule from overlapping on a target layer.

Property spelling is case-insensitive. Values must convert to the required boolean or integer type. Unknown or invalid properties produce warnings.

Tile matching

  • The target cell must be inside the target layer and not empty.
  • A tile in a positive input layer accepts that exact tile.
  • A tile in an InputNot layer rejects that exact tile.
  • With only positive layers, an empty rule coordinate accepts tiles not used elsewhere by the positive pattern.
  • With positive and negative layers together, positive coordinates must match an allowed tile and no negative tile may match.

Object Group matching

Input and InputNot layers may also be Object Groups. A rule object compares its shape, translated position, dimensions, polygon data, and custom properties. Name and type are compared when their rule values are non-empty. A rule property value of * means the candidate must contain that property but its value may be anything.

All objects in a positive pattern must be found. A matching InputNot object pattern rejects the rule.

Applying and interactive mode

  • Reload rereads rules.txt, nested lists, and rule TMX files.
  • Apply runs all loaded rules on the complete target map.
  • Interactive reruns relevant rules when tile regions or map objects are added, changed, or removed.

Rules run in load order. The changed region produced by one rule is passed to following rules, allowing multi-stage pipelines. Application is stored as Apply AutoMap rules in the Undo stack.

Test new rule sets on a copy. Interactive mode can trigger a large pipeline after a small edit, especially with a large AutomappingRadius or recursive output dependencies.

Troubleshooting

Message or symptomCheck
No rules loadedThe target TMX is saved and rules.txt is beside it.
No input/output region layerAdd Regions, or both RegionsInput and RegionsOutput.
Layer not recognizedCheck the underscore and accepted prefix.
Rule never matchesVerify target layer type/name, non-empty cells, input grouping, and InputNot exclusions.

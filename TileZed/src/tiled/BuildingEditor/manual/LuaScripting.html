Lua scripting in BuildingEd

BuildingEd embeds Lua 5.2 for editor automation. Choose Building > Run Lua Script..., or open Building > Lua Console. F5 reruns the last BuildingEd script while the console is in BuildingEd mode.

The global building is a transactional view of the current document. A successful script is committed as one Undo operation. A syntax error, runtime error, or user cancellation changes nothing in the document. The current API version is building.apiVersion == 2.

The global scriptDirectory contains the absolute directory of the running script. API indexes and coordinates are zero-based. Lua list tables returned by the API are iterated normally with ipairs().

Quick inspection

print(building:width(), building:height())

for floorIndex = 0, building:floorCount() - 1 do
    local level = building:floorLevel(floorIndex)
    print("level", level, "objects", building:objectCount(level))
end

for roomIndex = 0, building:roomCount() - 1 do
    print(roomIndex, building:roomName(roomIndex))
end

Rooms

local level = building:currentLevel()
local roomIndex = 0
building:setRoom(level, 5, 8, roomIndex)
building:fillRoom(level, 10, 10, 4, 3, roomIndex)
building:setRoom(level, 5, 8, -1) -- erase assignment

User-tile and grime layers

These functions access the per-floor string tile grids used for grime and user-tile overrides. Structural floors, walls, doors and furniture remain generated from rooms and BuildingEd objects; these functions intentionally do not overwrite that generated structure.

local level = building:currentLevel()
for _, layer in ipairs(building:userLayerNames(level)) do print(layer) end
print(building:tileAt(level, "FloorGrime", 3, 4))
building:placeTile(level, "FloorGrime", 3, 4, "floors_overlay_01_12")
building:replaceTile(level, "FloorGrime", 3, 4,
    "floors_overlay_01_12", "floors_overlay_01_13")
building:deleteTile(level, "FloorGrime", 3, 4)
FunctionResult or effect
userLayerNames(level)One-based list of existing grid names.
userTileAt(level,layer,x,y)Tile name or an empty string.
setUserTile(level,layer,x,y,tileName)Records one override and creates the named grid when needed.
tileAt(level,layer,x,y)Alias returning the exact tile name or an empty string.
placeTile(level,layer,x,y,tileName)Validates and places one known tile; creates the layer when needed.
deleteTile(level,layer,x,y[,tileName])Deletes by position. With a name, deletion occurs only on an exact match. Returns a boolean.
deleteTilesByName(level,layer,tileName)Deletes all exact matches in one layer and returns the count.
replaceTile(level,layer,x,y,oldName,newName)Conditionally replaces one position and returns a boolean.
replaceTilesByName(level,layer,oldName,newName)Replaces every exact match in one layer and returns the count.

Qt application actions

The global app queues existing BuildingEd actions. They execute only after the script succeeds and its transactional edits enter the Undo stack.

FunctionResult or effect
app:availableActions()Returns save, saveAs, exportTMX, exportBinary, buildingProperties, rooms, floors, and tiles.
app:invoke(actionName)Queues a whitelisted action; dialog actions open the normal Qt window.
app:invoke("exportTMX")
app:invoke("exportBinary")
Arbitrary QObject construction, widget ownership, signals and slots are not exposed. In-game map feature generation belongs to WorldEd and cannot be invoked on a BuildingEd document.

Errors, cancellation, and trust

Invalid levels, indexes, coordinates, rectangles, or object destinations raise a Lua error. Long scripts process UI events every 10,000 Lua instructions and can be cancelled from the progress dialog.

BuildingEd currently opens Lua's standard libraries, including file and OS functions. Run only scripts you trust. These are editor scripts, not Project Zomboid gameplay scripts.
